SEC-01: Hardcoded Database Credentials & Master Azure Storage Account Keys
Critical

Affected Components: MiddleWare/Shared/DependancyManager.cs (Line 20), BusinessLayer/Manager/FileManager.cs (Line 26)

Vulnerability Description

Plaintext production SQL Server credentials and Azure Blob Storage master keys are hardcoded into compiled C# classes rather than loaded from environment variables or key vaults.

// DependancyManager.cs (Line 20)
options.UseSqlServer("Server=ones.database.windows.net,1433;Initial Catalog=HIRES;User ID=vijisrk;Password=Thayasrk22@@;...")

// FileManager.cs (Line 26)
_blobServiceClient = new BlobServiceClient("DefaultEndpointsProtocol=https;AccountName=hiresblob;AccountKey=XPt9HT6x...==");
Remediation Steps

1. Immediately rotate the database password and Azure Storage keys in the Azure Portal.

2. Refactor code to inject IConfiguration dynamically:

public static void ConfigureAPI(IServiceCollection _services, IConfiguration configuration)
{
    _services.AddDbContext<EFContexts>(options =>
        options.UseSqlServer(configuration.GetConnectionString("DefaultConnection"))
               .UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking));
}
SEC-02: Unenforced Route Authorization Attributes on Critical Endpoints
High

Affected Components: UserController.cs, ConsultancyController.cs, JobOpeningController.cs

Vulnerability Description

Several controller endpoints have their authorization annotations commented out (e.g. //[ApiAuthorize("AddUser")]) and use fallback dummy user contexts (context ?? GetDummyUserContext()), allowing unauthenticated actors to execute state-modifying requests.

Remediation Steps

Apply [Authorize] across all mutating endpoints and reject requests without valid JWT claims:

[HttpPost]
[Route("Add")]
[Authorize]
public Task<Result<UserDto>> AddUser(UserDtoForInsert User)
{
    return ExecuteAsync<UserDto>(async () =>
    {
        var context = GetUserContext();
        if (context == null || context.UserId <= 0)
            throw new UnauthorizedAccessException("Authorization token is required.");

        return await mgr.AddUser(User, context);
    });
}
SEC-03: Overly Permissive Wildcard CORS Policy (AllowAnyOrigin)
High

Affected Component: MiddleWare/Program.cs (Line 14)

Vulnerability Description

builder.AllowAnyOrigin().AllowAnyMethod().AllowAnyHeader() allows any malicious site to issue cross-origin requests to your API.

Remediation Steps

Restrict CORS specifically to trusted domains:

builder.Services.AddCors(options =>
{
    options.AddPolicy("CorsPolicy", policy =>
    {
        policy.WithOrigins(
            "https://www.chathire.com",
            "https://chathire.com",
            "http://localhost:4200" // Dev only
        )
        .AllowAnyHeader()
        .AllowAnyMethod()
        .AllowCredentials();
    });
});
SEC-04: Server-Side Request Forgery (SSRF) Risk in Scraper Service
Medium

Affected Component: BusinessLayer/Services/LinkedInScraperService.cs

Vulnerability Description

User-supplied URLs are fetched directly by the server via HttpClient without validating destination hostnames or checking private IP addresses.

Remediation Steps

Validate that input URLs are strictly http/https and belong to LinkedIn domains before initiating network calls:

private bool IsSafeScrapeUrl(string rawUrl)
{
    if (!Uri.TryCreate(rawUrl, UriKind.Absolute, out var uri)) return false;
    if (uri.Scheme != Uri.UriSchemeHttp && uri.Scheme != Uri.UriSchemeHttps) return false;
    if (IPAddress.TryParse(uri.Host, out _) || uri.IsLoopback) return false;

    return uri.Host.EndsWith("linkedin.com", StringComparison.OrdinalIgnoreCase);
}
SEC-05: File Upload Extension & MIME Whitelisting
Medium

Affected Component: BusinessLayer/Manager/FileManager.cs

Vulnerability Description

File extensions are taken directly from the client filename without enforcing allowed extension lists or checking binary signatures.

Remediation Steps

Enforce strict image extension whitelisting (.png, .jpg, .jpeg, .webp):

private static readonly HashSet<string> AllowedExtensions = new(StringComparer.OrdinalIgnoreCase)
{
    ".png", ".jpg", ".jpeg", ".webp"
};

public static bool IsValidImageExtension(string fileName)
{
    var ext = Path.GetExtension(fileName);
    return !string.IsNullOrEmpty(ext) && AllowedExtensions.Contains(ext);
}
SEC-06: Missing Rate Limiting on OTP Verification & Authentication Routes
Low

Affected Components: UserController.cs, TokenController.cs

Vulnerability Description

Lack of request throttling enables attackers to brute-force 6-digit OTP codes or exhaust Resend email credits by flooding /ResendOtp.

Remediation Steps

Configure ASP.NET Core built-in rate limiting in Program.cs to cap OTP requests to 5 per minute.

✅ Security Hardening Checklist

  • 1. Rotate Secrets: Regenerate Azure SQL database password & Azure Storage account keys in Azure Portal.
  • 2. Clean Source Files: Remove hardcoded credentials from DependancyManager.cs & FileManager.cs.
  • 3. Enforce CORS Restrictions: Update Program.cs CORS to allow only chathire.com & localhost:4200.
  • 4. Re-enable Route Authorization: Reinstate [Authorize] guards on mutating controller actions.
  • 5. Protect Scraper from SSRF: Restrict outbound scraping URLs strictly to *.linkedin.com domains.
  • 6. Validate Uploaded Images: Enforce strict file extension checks for logo/profile uploads.
  • 7. Implement Rate Limiting: Limit OTP generation and verification to 5 requests per minute.
